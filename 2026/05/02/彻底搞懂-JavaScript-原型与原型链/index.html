# 告别 “克苏鲁神话”：彻底搞懂 JavaScript 原型与原型链

在 JavaScript 的学习路径上，原型（Prototype）和原型链（Prototype Chain）被戏称为 “前端克苏鲁”。尤其是当 Object 和 Function 纠缠在一起时，那种 “鸡生蛋、蛋生鸡” 的逻辑常让初学者大脑宕机。

作为一个习惯了 C++ 严格类继承的开发者，在面对 JS 这种基于 “委托” 的动态系统时，我们需要一套清晰的底层逻辑。本文将通过两个核心概念和两条终极规律，帮你彻底拆解原型链。

# __proto__ 与 prototype

搞混原型链的根本原因，是没分清这两个长得极像的属性。

# __proto__ (隐式原型 - 找爹用的)

  • 谁有？ 几乎所有对象都有（包括函数）。
  • 干嘛的？ 它是对象的 “寻祖指针”。当你访问一个属性但对象本身没有时，JS 引擎会顺着 __proto__ 去上级原型对象里找。
  • 指向谁？ 指向创建该对象的构造函数的 prototype 。

# prototype (显式原型 - 给儿子的遗产)

  • 谁有？ 只有函数（Function）才有。
  • 干嘛的？ 它是构造函数为其实例准备的 “公共仓库”。
  • 指向谁？ 指向该函数的原型对象。

# 原型链的闭环法则

# 原型链的终点

所有的对象都有 __proto__ 属性，指向它的原型对象。这形成了一个单向链表：

  • 对象 A 的 __proto__ --> 原型对象 B
  • 原型对象 B 的 __proto__ --> 原型对象 C
  • ... 一直往上指，直到 Object.prototype
  • Object.prototype.__proto__ --> null

结论：原型链是有终点的，它的尽头是 null 。

# Function 与 Object

  • 函数也是对象：所有的函数（包括 Object() 、 Array() 以及你写的自定义函数）都是由 Function 构造函数实例化的。
  • 自己生自己： Function 作为一个函数，它也是由 Function 产生的，所以 Function.__proto__ === Function.prototype 。
  • 殊途同归： Function.prototype 本质上也是一个普通对象。既然是对象，它的 __proto__ 最终也要认祖归宗，指向 Object.prototype 。

# 当 Object 遇见 Function

我们可以把 JS 的原型体系看作两套交织的系统：

身份属性逻辑关系
实例身份__proto__向上寻找继承的方法（如 toString , call ）
构造者身份prototype向下传递共享的方法（如 Array.push , Object.keys ）
